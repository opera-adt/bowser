# Imported feature identity

Bowser keeps a GeoJSON feature's string or finite numeric `id` when importing it.
This is separate from attributes such as `properties.id` or `properties.name`.
Zero and empty-string IDs are retained; number `1` and string `"1"` are different.
Unsupported ID types are ignored rather than converted into guessed strings.

A unique ID lets a point/polygon selection and its chart color remain attached
to the same imported feature when the collection's order changes. Its source
record keeps the original ID, source layer when explicitly declared, and the
current feature index. Saved projects retain that information. Chart geometry
and measurements remain the snapshot originally selected; this is not a feature
editing/synchronization tool.

## Combined source layers

A converted small vector collection can explicitly identify the property that
holds its source layer name:

```json
{
  "type": "FeatureCollection",
  "bowser_source_layer_property": "source_layer",
  "features": [
    { "type": "Feature", "id": 1,
      "properties": { "source_layer": "regions", "name": "Region A" },
      "geometry": { "type": "Point", "coordinates": [3, 4] } }
  ]
}
```

Bowser preserves this collection annotation and namespaces IDs by that declared
source layer. Ordinary attributes named `layer` or `source_layer` do not establish
provenance by themselves. The collision-safe converter annotation is supplied
by the companion vector-property repair; direct GeoJSON with unique IDs works
without a converter change.

IDs missing or repeated within the same namespace use the previous index-based
selection behavior. No feature is silently merged or dropped. If a previously
unique ID disappears or becomes ambiguous, its old chart color is not assigned
to an unrelated feature now occupying its former index.

## Compatibility and limits

- Existing projects with index-only source records keep their existing behavior;
  Bowser cannot reconstruct missing historical IDs. Old records are not silently
  upgraded to an assumed identity. Reimport/reselect when appropriate.
- Identity is local to an overlay. Importing a file again creates another overlay;
  this does not deduplicate separate files or processing areas globally.
- Editor-generated Drawings IDs keep their existing selection behavior; they
  are not imported source IDs and can be regenerated by editing tools.
- KML/GPX/CSV features without GeoJSON IDs remain index-based. This change does not
  invent IDs from names, attribute values or polygon coordinates.
- This does not add a GeoPackage layer chooser, change reprojection, or recover
  IDs that were already lost upstream. PMTiles display features remain distinct
  from complete source geometries suitable for polygon statistics.
- JavaScript parses JSON numbers as numbers; producers needing arbitrary-precision
  integer identifiers should encode them as strings.
- The map renderer still uses its own generated index IDs for styling. Preserved
  source IDs live in the imported collection and chart provenance; they do not
  replace the renderer's internal IDs.

No scientific processing, raster values, masks, references or polygon statistics
are changed by preserving this import metadata.
